Preserved aesthetics The floating rounded bottom-nav survives — but now holds three destinations, not five. The composer rides above the tabs on every route; the conversation is the ?pane=channel view, reached from the composer. Exactly one composer exists in the DOM (the desktop composer lives only in the right panel).

  • Three destinations, not a loop. Home is the personalised actionable brief (new-user explainer, "Find a hackathon", progressive profile, then decisions / deadlines / recommendations / progress — one primary action per card). Discover is an account-level surface that works before any project. Projects lists real builds with a secondary create path (idea-first, existing-code import).
  • Plan / Build / Submission are project-local. They are tabs inside a project (and mobile panes), never global destinations. Deep links to them carry ?project=.
  • Saving is not building. Browsing or Saving an opportunity never creates an empty project. "Explore ideas for this hackathon" is the single commit: it continues an existing project already linked to the contest, or creates exactly one — never a duplicate — and the conversation retargets to that project.
  • Honesty is structural. No invented numeric fit score, no win probability; eligibility stays UNKNOWN without evidence; a partial feed failure is a named gap. Invalid ?project= ids are MISSING, never a silent fallback.
  • Contracts preserved. Runtime / authorization / approvals / budgets / evidence boundaries are unchanged; the redesign is a presentation + navigation layer over the same REST + Flue surface.
  • Verified (LOCAL UI-state proof, composed build): tests/browser/workspace.spec.ts (17), discovery.spec.ts (9), and the new discovery-journey.spec.ts (scenarios A–G, one account end-to-end) are green; no horizontal overflow at 390 / 768 / 1440. This is a UI-state proof — real-data/auth behavior is covered by the integration suites, not these stubs.
