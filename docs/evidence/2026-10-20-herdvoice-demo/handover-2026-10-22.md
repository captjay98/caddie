## 3. Two Remaining Defects in the Generated HerdVoice App (Why It Was Rolled Back)

1. **Invalid AI tier in `src/server.ts`:**
   - HerdVoice's generated server calls `c.env.CADDIE.ai({ messages, json: true, tier: "balanced" })`.
   - The platform (`apps/app/src/server/app-ai.ts`) only accepts `tier?: "fast" | "super"` and returns `{ ok: false, reason: "invalid_request", message: 'Choose tier "fast" or "super".' }`.
   - Result: `app_ai_usage` in prod D1 has **0 settled rows** for HerdVoice; every live symptom analysis fell back to "Analysis pending".
2. **In-memory server arrays instead of `env.DB` (D1):**
   - Because HerdVoice's PRD approved `"MVP storage: in memory + device localStorage copy"`, `src/server.ts` stores `animals` and `cases` in JS arrays (`const animals: Animal[] = []`) and only has the scaffold's `migrations/0000_caddie_auth.sql`.
   - Result: server state vanishes whenever the preview isolate (or a published Worker) restarts.

## 4. Important Finding on Retry / Continue Dispatch (`build-workflow.ts`)

While preparing to kick off the rebuild with repair instructions, I traced how user instructions reach a `blocked` build on retry:

1. **`POST /api/projects/:projectId/workflow/retry`** (`apps/app/src/server/routes/build-workflow.ts:283`) currently calls:
   ```ts
   const snapshot = await retryWorkflow(c.env.DB, scope, input.key, undefined, c.env);
   const deliver = deliverFor(c);
   if (deliver) await dispatchPendingWorkflow(c.env.DB, scope, deliver);
   ```
   It passes `undefined` for `request`, and `retryWorkflow` (`apps/app/src/server/build-workflow.ts:1096`) does **not** carry a parked `continue:...` `pendingBody` the way `resumePlanning` (line 1078) does.
2. **Conversely, `continueNamedProject`** (`apps/app/src/server/coordinator-host.ts:838` → `continueProjectFromChat(..., resumeBlocked: true)` → `retryWorkflow(db, target, recoveryKey, input.request, limits)`) **does** write `request` into `pendingBody` (`... User request: ${request}`) and records `recoveryKey` in `workflow_resumes`, flipping `phase` to `'building'`, **but never calls `dispatchPendingWorkflow`** (and the browser's old `pendingKey` auto-resume effect in `ProjectWorkflow.tsx:99` was removed in R02).
3. **Also note:** A rolled-back sandbox session starts from Feature 1's save-point image (created on 2026-10-20), so `test/setup/caddie.ts` inside that old sandbox snapshot predates commit `19f9d1a` (which only applies to newly scaffolded projects). Thus the repair prompt itself must explicitly instruct the builder to use `tier: "super"` (or `"fast"`) and `env.DB` with `migrations/0001_herd.sql`.
