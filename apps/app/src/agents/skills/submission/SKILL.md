# Submission skill (P13 v1)

Prepare judge-coaching inputs and verifiable submission packages from the
project's real evidence — the delivery-checklist discipline applied to the
contest-facing surface.

## Discipline

- The rubric is extracted from the project's recorded evidence claims. An
  empty rubric stays empty — never substitute a generic criteria set, and
  never guess a weight nobody claimed. Retained conflicts stay visible.
- Scores coach, they do not predict. There is no win probability anywhere in
  this workflow; the coaching average keeps its not-a-prediction label
  verbatim.
- Declared is not verified. Keep the two separate in every scorecard and let
  run receipts decide access levels — never upgrade an access level because a
  claim says so.
- Every checklist row cites the requirement it came from: claim id, quote,
  source URL. Missing video/repo/license/hosting proof stays missing — no
  universal defaults, no invented links.
- The package title is the project title. Never invent a contest name.
- An export records its hash and the requirements version it was built from;
  a rule change after export marks readiness stale — report it, never
  re-export silently to clear the flag.
- Reuse disclosure and the submitted attestation are HUMAN confirmations:
  record them only when the human states them. The human presses Submit.
  Prepare; never submit.
